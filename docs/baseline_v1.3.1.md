# Baseline v1.3.1 against XFOIL

Measured 2026-10-08 on commit `89a1e0d` of branch `worktree-m1-benchmark`. Solver numerics are those of commit `be54d0a` (v1.3.1): M1 changed no solver code. Machine: x86_64, Python 3.14.7, one BLAS thread per worker process.

Reference: XFOIL 6.99 (`xfoil-6.99-25.fc44.x86_64`, run as `xvfb-run -a xfoil`), 160 `PANE` nodes, N_crit 9, free transition, Mach 0, `ITER 200`, one retry per skipped angle. Both codes read the same canonical coordinate file (160 panels; NACA sections with the open trailing edge of NACA Report 460).

Methods of v1.3.1: inviscid (`solve_flow`), one-way (`solve_flow` with Re, the default viscous path), transpiration VII (`solve_vii`, 200 iterations, tol 1e-3, e^n, N_crit 9), Newton VII (`solve_vii_newton`, 60 iterations, tol 1e-4) on a small subset.

Rules: alpha -4 to 20 deg in 1 deg steps. Attached-flow filter: from -4 deg up to, not including, the first positive angle where XFOIL's Cl reaches 0.9 x its maximum. A point is used only if XFOIL converged and the method converged; points the method did not converge on are counted in 'not converged (excluded)'. Inviscid has no drag. 'Paneling sensitivity (160 vs 240)' is the difference between the two XFOIL runs; for the sharp-edged section (E387, gap 0) it is a lower bound, because XFOIL's result there keeps changing with node count. Accuracy targets are judged on open-trailing-edge sections only.

The one-way path of v1.3.1 adds drag to the inviscid solution without changing it, so its Cl and Cm errors are identical to the inviscid ones (in the plots the inviscid curve lies under the one-way curve). One-way and inviscid results have no convergence criterion in v1.3.1 and are counted as converged.

Provisional targets (SPEC.md 4.1, validated range, attached flow): mean |dCl| <= 0.03, mean relative |dCd| <= 10%, mean |dCm| <= 0.01.
